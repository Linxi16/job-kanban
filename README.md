**https://linxi16.github.io/job-kanban/**

- 手机浏览器直接输这个网址（不用输文件名，根路径已可直接打开）
- **建议「添加到主屏幕」**，之后像 App 一样一键打开：
  - iPhone Safari：分享 → 添加到主屏幕
  - Android Chrome：⋮ → 添加到主屏幕

### 看板能做什么（v2.0）

- **展示全部岗位**：抓到的每一条都进页面（当前 500 + 500），不再只显示推荐岗；默认按推荐指数排序，低分岗位也能翻到
- **搜索**：排序栏右侧可切换「岗位 / 公司」两种索引，输入关键词即时过滤
- **筛选**：推荐岗位 / 接受应届生 / 双休 / BP＆管培生
- **分批加载**：首屏只渲染 50 条，点「加载更多」继续，避免一次性渲染上千张卡片把手机拖卡
- **工作模块**：从 JD 职责里提炼被提及最多的 3 项核心工作内容（如 招聘 / 行政 / SSC），只显示名称，不显示百分比
- **接受应届生**：明确显示 是 / 否 / ？（无法判断时才给「？」）
- **页面体积**：约 2.1 MB，服务器 gzip 后实际下载约 600 KB；每次出新数据后的**首次**打开才会重新下载，之后走浏览器缓存

### 首次使用（只需做一次）

1. 打开上面的网址
2. 点「刷新数据」按钮，弹出框里粘贴一个 GitHub 令牌
   - 令牌申请：https://github.com/settings/tokens → Generate new token (classic) → 勾选 `repo` 和 `workflow`
   - 令牌只保存在**你本机浏览器**里，不会上传到任何地方
3. 之后每天最多可刷新 **5 次**，每日凌晨自动重置；按钮下方进度条（黄→绿）会实时显示云端进度，按钮下方还有一行小字显示「上次刷新：x年x月x日x时x分」（北京时间）

> 安全提示：令牌等于密码，不要发给别人。用完可在 https://github.com/settings/tokens 随时删除或重新生成（删除后重新粘贴一个新令牌即可）。

单次更新耗时约 **4–6 分钟**（两个平台各按城市切成 3 片，共 **6 个任务并行**）：

| 任务（并行） | 城市分片 | 规模 | 请求数 | 预计耗时 |
|---|---|---|---|---|
| 智联招聘 ×3 | 广州·佛山 / 深圳·东莞 / 中山·珠海 | 8 关键词 × 2 城市 × 2 页 | 每片 32 | ≈2.5 分钟 |
| 前程无忧 ×3 | 广州·佛山 / 深圳·东莞 / 中山·珠海 | 8 关键词 × 2 城市 × 3 页 | 每片 48 | ≈4 分钟 |
| 合并 → 评分 → 构建 → 发布 | – | – | – | ≈1.5 分钟 |

- 请求间隔 **3.8 秒**（用户指定）
- 分片之间是**并行**的，所以每片内部仍严格保持 3.8 秒间隔
- 总耗时由最慢的前程分片决定

⚠️ **并发说明**：同一站点同时有 3 个分片在请求，等效约 **0.8 次/秒**。若对方站点限流，日志里会出现失败计数上升、收录量下降——请留意每次运行的「失败 N」数字。

## 数据更新方式

**只支持手动触发**，没有任何定时任务。三种方式任选其一：

1. **看板页面上的「刷新数据」按钮**（手机、电脑均可）— 推荐，无需电脑
   - 首次点击会提示粘贴 GitHub 令牌（只存在本机浏览器，不会上传）
   - **每天最多 5 次**，每日凌晨自动重置
   - 点击时弹窗显示「今日剩余次数：X」；用完后提示「无剩余次数」
   - 按钮下方有彩色进度条（**黄色→绿色**渐变），实时显示云端抓取进度（0% → 100%），每 30 秒向云端查询一次；刷新结束或失败后自动隐藏
   - 进度按云端**全部 7 个任务**加权推算（6 个抓取分片 + 1 个构建发布），不会卡在 100%
   - 按钮下方一行小字：「上次刷新：2026年9月30日5时32分」（取自云端构建时刻，固定北京时间）
   - 刷新完成并重新载入后，页面底部弹出 5 秒提示：「今日新增 X 个岗位，其中推荐岗位 Y 个！」
     （X = 以本次刷新时刻为基准、往前 **24 小时**内发布的岗位数，按小时精确计算）
2. **手机 GitHub App** → 本仓库 → Actions → 「更新岗位数据」→ Run workflow
3. **网页** → https://github.com/Linxi16/job-kanban/actions → 「更新岗位数据」→ Run workflow

预演当前配置（不联网，只算请求数与预计耗时）：

```bash
node cloud/fetch-all.mjs --plan
```

## 抓取规模调整

在 `.github/workflows/update.yml` 里改环境变量（全局 `env:` 块，城市分片在 `strategy.matrix.include`）：

| 变量 | 含义 | 当前值 |
|---|---|---|
| `GAP_MS` | 请求间隔（毫秒） | 3800 |
| `ZL_KWS` / `QC_KWS` | 搜索关键词 | 8 个 |
| `ZL_PAGES` / `QC_PAGES` | 每个关键词翻几页 | 智联 2 / 前程 3 |
| `ZL_CAP` / `QC_CAP` | 单平台唯一岗位上限 | 2000 |
| 城市分片 | 在 `strategy.matrix.include` 里 | 3 片 × 2 城市 |

> 城市名必须在内置城市码表里，写错会在开跑前直接报错并列出可用城市（不会静默丢数据）。
> 前程无忧城市码经实测验证：广州 `030200`、佛山 `030600`、深圳 `040000`、东莞 `030800`、**珠海 `030500`**、**中山 `030700`**。
> 想调整分片粒度（比如改成 2 片或 6 片），改 `matrix.include` 的 `cities` 分组即可，两个平台都适用。

## 评分口径

- 基础分 50，加分上限 70，总分上限 100
- 达到 **75 分**才进入推荐列表
- 薪资过滤：**区间上限 < 6000 才过滤**（未标明薪资不误杀）
- 模块占比：只统计 JD 职责里提到的模块，按 5% 刻度分配，合计 100%
- 信息来源以 **JD 正文为准**，JD 未提及才参考发布信息

### JD 来源

- **智联招聘**：搜索页 SSR 里内嵌了完整 JD（`positionList[].jobDetailData.position.desc.description`），直接提取，
  **实测覆盖 501/503（99.6%）**，无需再逐条抓详情页——既省时间也不增加对方服务器压力
- **前程无忧**：接口返回即含 JD
- 若某条岗位确实拿不到 JD，会保留但不计入「按 JD 加分」，并在看板上标注

| | 本地 `岗位看板/` | 云端 `dist/`（Pages） |
|---|---|---|
| 页面设计 | 完全相同 | 完全相同 |
